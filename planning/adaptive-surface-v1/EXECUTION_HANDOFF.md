# Fresh-context execution handoff

Preparation/import is separate from implementation. Do not claim tasks, dispatch workers, prepare lane workspaces, run product gates, or change the runtime merely because plans have been staged or imported. Start implementation only under the root's execution authorization and current native claim. The root owns task lifecycle, integration, cross-project decisions and final acceptance.

## Layout and preparation order

Project Control's exclusive integrator lane owns CONTRACT → PACKETS → SURFACE → QUALIFY → RELEASE → epic. The context producer owns CONTEXT → TRACE → CONTROL; the observer-runtime producer owns JOBS → SKILL. Producers use `parallel_safe` task policies and `isolated_merge` workspaces, with SURFACE as their merge target. Skills remains one exclusive lane in its original dependency sequence; no independent Skills branches are implied.

After live validation and authorized implementation, root executes CONTRACT and PACKETS in the integrator lane, preserving existing obligations and dirty work. Record the reviewed foundation commit and compatible packet/contract receipts. Explicitly prepare the exclusive integrator destination at that foundation commit using native workflow workspace machinery before preparing either isolated producer. Root prepares both producer workspaces from that exact same recorded base and checks their native base and integrator bindings before dispatch. Do not prepare producers from a checkout that has advanced independently, assume a default HEAD is the foundation, or edit authoritative workspace state directly. If a workspace was already prepared against another base, inspect it and use supported reconciliation; preserve its work.

Within each producer lane, preserve the original task dependencies and advance only after current prerequisite gates and required foreign producer receipts pass. At SURFACE, root merges and reviews both producer artifacts into the prepared exclusive destination with native integration mechanics, resolving cross-lane conflicts centrally. Native done status in a producer workspace alone does not make its code available in the destination. Verify both artifact identities and merged behavioral gates before SURFACE qualification and before dependent QUALIFY or RELEASE. Aggregate epics retain every child-completion gate.

Skills may progress alongside independent Project Control work only when required cross-authority receipts are current. Inspect `planning/cross-authority.json` for each consumer; verify producer project UUID, task, gate, source and contract identity. In particular, Skills SEMANTICS consumes the reviewed Project Control CONTRACT receipt. Project Control consumers of Skills runtime/resource/routing/qualification receipts must await those compatible receipts. Never mark a foreign task done locally or replace receipt obligations with branch ordering.

## Bounded configured Codex workers

Root uses configured Codex subagents: `wf2-scout` for narrow locating, `wf2-researcher` for bounded source/authority investigation, `wf2-implementer` for coding and tests, and `wf2-reviewer` for consequential independent review. Do not use Project Control `delegate_task` or `local-coding-worker` for these assignments. Local workers remain observer infrastructure. Use the cheapest capable configured role; do not silently promote a worker or substitute controller execution when that role is unavailable. Root records an observable escalation trigger and requested/actual model and effort before escalation. A parallel head is unnecessary for this small fixed lane layout.

Start workers with fresh context and an explicit authoritative task/claim, lane, workspace path, recorded base commit, writable file ownership and read-only source limits. Give them the current task sheet from `planning/outcomes.json`, its referenced specs, prerequisites, acceptance cases and producer receipts rather than the whole program. Re-fetch historical module anchors before assigning concrete writable paths. Broad native scopes support complete task obligations; they are not permission for two writers to edit shared files in one checkout. Workers are not alone and must preserve unknown edits. Shared API, registry, packaging and conflicting integration edits return to root.

Each worker returns exact source identity and commit, changed paths, executed commands and evidence paths, acceptance-case coverage, counterevidence, limitations and unresolved conflicts. Package self-tests prove package consistency only. Skipped, missing or unavailable product gates remain unpassed. Root alone accepts, merges and finishes authoritative tasks and releases workers when their bounded assignment is returned.
