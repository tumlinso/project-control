7. External routing and evidence digests

Read the separate Codex companion first. The proposed four named roles pin both model and reasoning. Current official Codex documentation describes custom-agent model/MCP overrides [W01, W02]; the actual installed version and effective child settings still require verification.

The root controls decomposition and consequential decisions. A narrow scout locates files. A researcher performs one bounded MCP investigation and returns conclusions/evidence/uncertainty. An implementer owns one first-class task. An independent reviewer reopens decisive evidence and adversarially tests consequential claims. A helper's conversation is not a durable workflow lane, and Project Control's local-worker delegate_task is not Codex's native subagent spawning API.

Use work_profile as a routing requirement, never as a provider lock. Start with a routine worker for established patterns, a researcher for deep context, and an appropriately capable reviewer for hard/critical work. Do not put a detailed provider price table into task semantics. No model choice proves the agent has correct authority or capabilities.

MCP and permission checks

Research-only roles disable inherited workflow MCP and use the separately enforced observer with an allowlist excluding terminal_capture. Enumerate other inherited servers/plugins before adopting a profile. Do not share opaque parent write capabilities. The parent may still reapply live sandbox/approval overrides; a read-only role file alone does not prove filesystem isolation. Record actual effective settings and use a separate restricted session when needed.

The inspected user's root was Sol/medium with full-access/never-approval defaults. This package preserves those settings rather than silently rewriting them. Research isolation must be verified rather than inferred from the role name. The companion's renderer writes only a new staging directory and cannot replace live config.

Digest contract

A research answer identifies the question and scope, conclusions, exact supporting repository/path/ranges or task/interface IDs, source/authority revision, uncertainty and contradictory evidence, coverage gaps, and next action. Aim initially for at most 1,200 tokens or 6 KiB; complete material warnings outrank that soft target. Return raw full records only when the exact fields are needed.

The parent should not duplicate the exploration. Re-fetch only decisive, disputed or stale evidence, or delegate a targeted follow-up. Stop when the question is answered; do not exhaust pagination by default. No broad repeated polling, recursive researchers or unbounded fanout. Measure total usage where available and label estimates otherwise.

PC-WF2-A03 verifies inexpensive exploration before heavy fanout. D-stream work integrates the resulting contracts with authoritative profiles and operator guidance. The global launcher remains separate from role files. handoff/START_CONTROLLER.md is the short execution entry; the complete catalog is for reference, not mandatory context for every child.
