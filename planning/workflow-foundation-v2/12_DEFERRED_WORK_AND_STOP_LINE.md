# 12. Deferred work and stop line

This program does not move `.todo-orchestrator/` directories, rewrite all historical ledgers to the new format, merge repository Git histories, initialize a Todo authority for Codex, absorb ctxpp/CUDA/local-worker into one source product, implement a general LLM execution service inside Project Control, or develop unrelated Cellerator/GlassHelix science.

It does not delete useful old tests to create parity, remove immutable baseline releases needed for rollback, purge unrelated worktrees, or represent unsupported hardware/model access as completed work. A stable thin compatibility shim may remain at final closure; its complete later removal depends on a reviewed external-consumer inventory and the recorded support-window criteria.

A complex task may require more capable reasoning. Economy is not an excuse to force a weak worker through a correctness-critical decision. Escalate deliberately with observed execution policy and bounded context. There is no promised fixed percentage saving in subscription allowance.

The construction stop line is delivery of files and local package checks. The manual bootstrap stop line is verified additive import with no worker dispatch. The execution stop line is the accepted program's qualified paired release, explicit remaining limitations and only owned safe cleanup. Owner-only deployment steps can block final qualification without erasing completed implementation work.
