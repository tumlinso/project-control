# 1. Scope, decisions, and completion

WF2 makes Project Control one workflow product rather than an observatory bound to a separately discovered Todo kernel. It preserves a hard internal authority boundary and retains independently useful engines, especially cpp-context-compiler. The delivered files are a planning/bootstrap program, not an implemented merge.

## Authorized outcome

Move the existing Todo implementation under `project_control.workflow_core`, retain its semantics first, qualify parity against the old package, then evolve strict task profiles, lifecycle reconciliation, coherent snapshots, source retrieval, proposal freshness and MCP response economy. Rewrite maintained Skills consumers to supported interfaces and retain a bounded forwarding-only legacy surface. Keep existing state directories and project UUIDs. Preserve the old deployment while the new candidate is built and tested.

`workflow_core` deliberately does not collide with Project Control's existing `workflow.py` read-model module. The initial move should retain the donor's internal relative layout. A later review may refine internal submodules without weakening the single-authority invariant; it must not mix behavioral changes into the parity receipt.

The Codex companion stages role definitions and instructions so cheaper agents can absorb source context. The root model remains the user's choice. The live inspection showed Sol/medium; this package does not silently switch it to Astra. Codex settings and actual agent attempts are not properties of the task's semantic difficulty.

## Boundaries

Skills is not absorbed wholesale. Ctxpp, CUDA tooling and local-coding-worker retain distinct responsibilities and independently versioned contracts. Project Control owns workflow intent and task transactions; Git and actual source remain source authority, engines own their results, and the executor owns actual model/session execution.

No broad new biological or Cellerator/GlassHelix implementation is authorized by this epic. Their existing states may be used through sanitized exports/restored test copies and final bounded nonmutating compatibility reads. Do not repair their unrelated tasks or remove their worktrees. No UI platform, generic distributed scheduler, autonomous cost-purchasing system, or mandatory storage namespace migration is included.

## Autonomy after explicit controller launch

The later launch handoff authorizes ordinary engineering choices, scoped task refinements, candidate testing and non-destructive integration within this program. Record scope/interface changes through supported workflow operations. Missing privileges, destructive data loss, contradictory requirements and unavailable native contracts are real blockers, not invitations to bypass controls. Package construction and import do not launch agents or grant deployment permission on their own.

Completion means the new implementation, not a copied directory alone: independent parity, migration/read compatibility, one live transaction authority, standalone ctxpp, actual effective research routing, measured full-response economy and a qualified paired release. A rehearsal-only deployment must remain labelled rehearsal; a resource-unavailable test must remain blocked.
