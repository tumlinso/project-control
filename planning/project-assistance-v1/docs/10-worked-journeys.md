# 10. Worked product journeys

These examples describe intended behavior, not completed implementation or newly exposed MCP tools.

## A. Codex arrives at a warm decision

The user focuses Project Control on a changing packing path and its end-to-end cost. An external agent edits that subsystem. A cheap deterministic reconciliation observes the material delta and coalesces the burst. The gather behavior reads the relevant implementation, goal and existing results, then stores one short explanation with exact source identities.

When the agent asks through an existing discovery/inquiry route, Project Control retrieves the prepared explanation and checks its dependencies. It can say that the candidate moves work from execution into preparation, identify the missing reuse measurement, and point to the relevant test and source. It does not return a general lecture about GPUs or re-read every project README. If the implementation changed again, it refreshes the affected piece or labels the prior observation historical.

The improvement is not that Project Control ran more agents. It is that the next decision begins with the right evidence and a worthwhile question.

## B. The answer requires an experiment on the model's GPUs

The user asks the CLI to test a permitted mechanism under a bounded GPU grant. The reasoning frame prepares an experiment specification and reaches a wait. Its visible state and dependencies are saved, and its inference lease is released. The controller obtains the existing CUDA foreground lease, which can evict both warm inference instances through verified ownership cleanup.

A non-model runner compiles and executes the isolated test. No parent agent is occupying a model slot waiting for it. The measurement and source identities enter the evidence store. After the experiment releases its resources, the parent becomes runnable. It resumes only if the current power policy allows inference and explains the result with its limitations. A losing mechanism becomes a scoped negative finding, not an automatically abandoned project direction.

## C. Two parents would otherwise deadlock

Both physical slots are running foreground frames. Each requests a small child investigation with a distinct source scope. The controller records both dependencies, checkpoints both parents, and releases the model leases. It schedules the children under bounded root credits. Child completion wakes each matching parent generation once.

The semantic graph may expose the relationships for inspection, but a typed completion/version record—not model interpretation of a graph note—causes the wake-up. A failed child returns a failure observation. Neither parent retains a lease or blocks a dispatcher waiting for an MCP callback.

## D. Better experiments rather than endless ideas

A source comment claims an algorithm handles arbitrary support sizes. The assistant notices the existing tests cover only even sizes. In an authorized scratch window it creates an odd-size counterexample and runs it against the captured source. The failure is retained with the exact test, source version and output. The assistant suggests the smallest correction or next check, but does not modify canonical source or create a new Todo without authorization.

The same pattern applies to creative mechanisms: name an assumption, construct the cheapest experiment that can falsify it, retain a measured result, and revisit only when a relevant determinant changes. An unanswered high-value question is better than ten speculative optimization slogans.

## E. Long-term context without policing the user

At handoff, the assistant observes that recent work improves a narrow throughput number while the explicit goal concerns total repeated-work cost. It supplies a brief connection: the current result is promising in one regime, but preparation and reuse determine whether it serves the larger goal. It proposes the missing measurement and links the original goal and relevant evidence.

The user can redirect or dismiss that suggestion. The assistant records the changed focus and stops repeating it. It does not treat an inferred historical preference as a permanent constraint on new research.

## F. Quiet really means quiet

The user disables automatic work for a period and asks to free the GPUs. The controller blocks new automatic descendants, safely stops or finishes bounded owned work, verifies inference release, and persists the quiet/residency state. Health checks, source changes and service restart do not cause a new model load.

An explicit question can still retrieve current prepared evidence without inference. When fresh inference is needed, the controller explains the residency veto rather than secretly overriding it. After quiet expires, automatic work resumes only within a still-valid focus window and its remaining budget—not as a backlog storm.
