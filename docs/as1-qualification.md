# Adaptive surface qualification

`tests/as1/test_pc_as1_qualify.py` implements E2E-01 through E2E-05. The required
runner is:

```sh
/home/tumlinson/project-control/.venv/bin/python -m pytest \
  -p planning.adaptive-surface-v1.scripts.as1_pytest \
  tests/as1/test_pc_as1_qualify.py --as1-report=/tmp/pc-as1-qualify-cases.json
```

The observer journey provisions three disposable native authorities, publishes
source-bound orientation, relations and generator provenance through the actual
mutator frontend, and then uses public observer tools. It checks batch errors,
exact source hashes, canonical task lookup, gate evidence, cross-project trace
direction, generation changes, new consumers and cycles. Snippets are checked
against source bytes. A separate actual installed ctxpp/Clang producer execution
checks the C++ export consumer and preserves unknown compiler environment
closure. Declared dependencies are distinguished from compiler-resolved calls.

The coder journey claims a disposable native task, reads its native source,
publishes a finding using its actual opaque capability, checks replay, and
completes through the canonical kernel. The mutator independently validates,
diffs and applies a plan and amends a relation with real invalidation. Native
maintenance fixtures check dirty-source preservation, recovery, live-work
refusal and idempotent receipts. Child environments select current paired source
without changing the parent process's installed binding or authority.

The inference case requires the paired worker's executed
`as1-paired-realproof/1` receipt. The source-bound Skills consumer checks actual
busy admissions, completed scout jobs, real model usage, exact skill excerpts,
distinct model process identities, independent dispatcher/model restart,
retained evidence and unchanged source-read counts, owned GPU cleanup and
protected service preservation. PC additionally compares installed AS1 product
hashes to the current managed workspace. A CPU stale-selection fixture
supplements that mandatory real journey. Missing hardware proof fails; it is
never a skip or a substitute success. `AS1_SQA_CANDIDATE`, `AS1_SQA_PC_COMMIT`,
`AS1_SQA_SK_COMMIT`, `AS1_SQA_PROOF` and `AS1_SQA_REPORT` identify final artifacts.

The economics case invokes actual old and new MCP tools against the same Git
files and fixed semantic snapshot port. The old interpreter is the frozen
`cuda-reconciliation-3a55e7c-20261003` release with manifest SHA256
`e01182edf95a08378d745736922d81b2db7b834699dbe625c05249cefd0498b8`.
Its deployment binding is retained in the child. Both read at the identical Git
revision and return the same required source, task, unexecuted gate and
provenance facts. The report counts all discovered schemas, instructions,
request bytes and returned wire content, calls, retries, repeated reads and
latency. Model tokens are null/unmetered because this comparison runs no
inference. It supplies no monetary equivalence, GPU/energy comparison,
population timing claim or historical baseline for the new cross-project trace.

Evidence is retained in
`planning/adaptive-surface-v1/validation/qualification/`. The conformance index
preserves exact executed reports and their hashes, current product/test hashes
and producer receipt references. E2E-05 requires every local producer case,
executed SQA-01 through SQA-03, hash-matching real proof and independent review
with executed verification of each finding. Historical frozen native gates
remain intact; changed CONTROL/public source is covered by later current
execution. An earlier combined report contributes only its passing MUT cases;
its API fixture failures are separately recorded and superseded by the final
passing public report.

Qualification completion requires the full runner to pass all five required
cases, including real inference and current conformance. Partial runs and the
CPU stale-selection supplement do not establish complete E2E-03 coverage.
Canonical runtime activation, rollback/cutover acceptance, and final task
lifecycle remain with the root controller.
