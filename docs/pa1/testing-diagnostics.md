## Preflight and source checks

Before execution, record the exact source commit and dirty-file manifest, selected release path and manifest digest, receiver manifest/fingerprint, and installed CLI/runtime/model identities. Resolve the fixture project, source, and skill through the supported workspace/skill inventory and record their stable IDs, roots, and content hashes. Compare source, installed candidate, and receiver hashes; stop before an expensive case if a required fixture is absent, stale, ambiguous, or resolves outside the expected root. Do not invent replacement fixtures.

Run source checks before live qualification, with separate command records and result rows. First run the focused tests named in the main handoff against the frozen candidate source. Then run only the existing source suites required by the case map in [`live-qualification-plan.md`](live-qualification-plan.md) and [`live-qualification-plan.json`](live-qualification-plan.json), once. Do not label source or fixture results as live acceptance. Compare failures with [`acceptance-results.json`](acceptance-results.json), [`baseline-tests.json`](baseline-tests.json), and candidate-tied receipts: classify each as known baseline, candidate regression, environment/fixture blocker, or unresolved. Keep that comparison bounded to implicated cases; do not begin a repository-wide issue search. Preserve the identity distinction: source checks target commit `b9806e2373a97236f6bc73ec970238cef4dfb371`; installed checks must independently verify the selected R10 interpreter, module/CLI roots, and manifest from their own receipts.

## Live diagnosis within the declared pass

Preserve the main handoff's per-case order, limits, scratch paths, resource admission, veto behavior, and cleanup. Before each costly action, verify its exact prerequisites and record missing fixtures or permissions as `blocked` with evidence. Keep inference, CPU LAB, CUDA LAB, and model-free lifecycle evidence as distinct classes. Treat readiness as phased: while the release veto is active and inference is stopped, record health/version and HTTP `/readyz` behavior separately from inference readiness; do not assume the veto dictates the HTTP readiness response; after the explicit release and startup, require the installed harness and runtime status to confirm verified readiness and candidate identity. Health alone is not inference readiness.

- For the known CPU `lab_planner_incomplete_proposal` failure, inspect the `experiment-plan-v1` proposal against the exact required-key contract and non-empty fields for an unfinished proposal (citations, artifacts, argv, measurements, hypothesis, and stop rule). Capture validator/schema version, redacted structural errors, and durable planning/run-interruption events from private artifacts. The transient CLI wrapper may discard child stderr and expose only `lab_transient_execution_failed`; record that boundary instead of treating the generic message as the root cause. Determine whether the proposal is incomplete, malformed, or inconsistent with the schema. Keep prompts, source snippets, credentials, and unredacted model output private; do not add them to the shared report. Confirm whether an effect was created before classifying the outcome. Do not change the schema, repair the proposal, or retry it in this pass.
- For slow grounded inquiries, record monotonic timestamps and elapsed durations for cold startup/acquisition, inquiry wall time, each poll wait, skill duration, direct role open/gather/synthesis, each server request's queue/prompt/decode/cleanup where exposed, tool dispatch and return, broker wait/close, cleanup, and total wall time. Preserve raw provider usage/response metadata only in private artifacts, including separate reasoning and visible-token usage when available. Existing R7 observations showed a 229-second answer plus 21-second shutdown; older R6 role calls took about 7.3 and 2.6 seconds. These are historical comparisons, not R10 baselines. Earlier traces also showed calls below nine seconds alongside 55–66 second gaps; locate the delay by stage and report uncertainty when a boundary was not observed. Do not infer that the model itself consumed the missing time.
- For the role calls, record requested and effective role, context/reasoning/visible-output budgets, clipped values and clipping reasons, layer-split assignment, model/server PID and start identity, and resource use. Check the idle-eviction configuration and, where the declared pass provides a sufficient observation interval, server residency; label an unobserved 15-minute interval unvalidated rather than adding a standalone wait; separately verify that a qualifying outside CUDA request triggers owner-mediated yield/release and that inference rewarms after CUDA cleanup. Do not perform tuning or calibration sweeps.
- Exercise the already-planned cancellation and restart scenarios with exact scope, process, and effect identities. The current LAB flow samples cancellation before/after its synchronous investigation turn; distinguish a durable cancellation request that waits for the bounded turn from immediate inference interruption; do not classify deferred cancellation alone as a defect. Measure cancel request-to-terminal/cleanup latency where available and verify the effect fence prevents late or duplicate effects. Separate pre-effect cancellation, post-effect cleanup, and unknown-effect recovery. A graceful stop/start is not a crash test. Only test crash recovery through an already-authorized isolated scratch runner with exact PID/start identity and recorded phase markers; never kill the host inference service or an unrelated process. Preserve state and receipts, and never replay an effect whose outcome is unknown. A cancellation receipt alone is not cleanup proof; reconcile scope/effect receipts with final census.
