# Controller decisions for opt-in assistance

Keep one trusted controller behind the CLI and line-oriented chat. Status and
time-control commands open private state directly and never start JobService
dispatch threads, connect a model, or keep a model lease while waiting for input.
An explicit ask may use the existing broker. Model or source prose can propose
an action, but cannot create a user goal, focus grant, scratch grant or residency
permission. The operator command path supplies trusted input provenance.

Keep demand-only and notifications-off defaults. A focus description is useful
without enabling automatic work; an explicit automatic window names the project,
source paths, expiry and resource ceiling. Store its goal card separately from
power enforcement metadata. Quiet expiry does not revive an expired focus, and
inference release remains a separate persistent veto until explicit resume.

Use the existing private broker and two execution threads for preparation. An
automatic root and its descendants retain their sealed automatic origin, use
the same cumulative six-turn frame accounting, and occupy at most one model
slot. Keep automatic records out of public inquiry admission, polling, logs and
exact-answer cache. Foreground questions may use both slots after a cooperative
slice boundary; waiting or deferred preparation owns no model session.

Attention state is bounded durable controller metadata beside the private job
database, not a new scheduler or Todo queue. Fingerprint actual opted-in source
bytes and declared configuration determinants. Exclude private service outputs,
notebook bodies, logs, Git bookkeeping, experiment directories and known generated
outputs from automatic change nomination. Seed a baseline without inference,
coalesce an edit burst, reconcile after restart, suppress unchanged input and
cool down failures. Dispatch rechecks current scope, focus, quiet, veto and
cumulative window limits. A rapidly changing input is deferred until stable.

Retain successful preparation as advisory notebook context with original
witnesses and current determinants. A requested decision-linked handoff ranks
user goals above inferred suggestions, preserves conflicts and cheap proposed
verification, and respects persistent dismissals. It cannot publish canonical
findings or create project tasks. Automatic notifications remain disabled.

These are root integration choices for the next claimed outcome. They are not
implemented behavior or executed live usefulness qualification.
